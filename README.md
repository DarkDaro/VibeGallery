# VibeGallery

Офлайн-галерея видеофайлов для Windows: папки с видео индексируются в
локальную библиотеку, получают миниатюры и метаданные, собираются в теги,
коллекции и плейлисты. Файлы остаются на своих местах, приложение не
копирует их в свое хранилище и не отправляет ничего в сеть.

Статус: ранняя стадия. Ядро (база, сканер, наблюдение за папками,
миниатюры, IPC) готово, плеер и экраны библиотеки в разработке.

## Зачем еще одна галерея

У любого, кто видел десяток галерей, есть право спросить: зачем эта.
Ответ простой: она не открывает новую категорию. Это инструмент под
конкретный сценарий. У тебя на диске лежат годы съемок и скачанных
фильмов, ты помнишь их по кадрам, а не по именам файлов, и ты не хочешь
заливать это в облако или поднимать медиасервер ради просмотра за тем же
столом.

Если сценарий не твой, ниже есть раздел «Кому не нужно». Это нормально,
и спорить с этим нечем.

## Какую задачу решает

1. Видео с телефона, камеры, скринкасты, скачанные фильмы лежат в папках.
   Имя `IMG_2041.MOV` не говорит ничего.
2. Проводник показывает список файлов и, в лучшем случае, одно превью.
   Найти «то видео, где дети в снегу» через проводник нельзя.
3. Облачные галереи требуют загрузку, аккаунт, подписку и доверие чужому
   серверу.
4. Медиасерверы (Plex, Jellyfin) решают стриминг по сети, но тянут за
   собой сервер, аккаунты, транскодирование и сетевые настройки, даже
   если смотреть надо за этим же компьютером.
5. Плееры (VLC, mpv) отлично проигрывают файл, но не ведут библиотеку:
   нет тегов, коллекций, истории просмотра и поиска по своим правилам.

VibeGallery закрывает эту дыру: локальный каталог собственных видео с
поиском и встроенным плеером.

## Суть

- Добавляешь корневые папки. Приложение обходит их, индексирует видео и
  не трогает остальные файлы.
- Для каждого видео: миниатюра (кадр с 10% длительности), длительность,
  разрешение, кодек. Все считается локально через ffmpeg и ffprobe.
- Повторный скан инкрементальный: сравниваются размер и время изменения,
  неизменившиеся файлы не пробуются заново.
- Наблюдение за папками: новый файл появляется в библиотеке сам,
  удаленный помечается отсутствующим.
- Теги, коллекции, плейлисты, умные фильтры и поиск хранятся в SQLite.
  Поиск и сравнение текста рассчитаны на кириллицу и регистр.
- Удаление только в корзину Windows, с подтверждением. Приложение не
  стирает файлы безвозвратно.
- Ничего не копируется и не перекодируется: путь к файлу остается один.

## Почему так

- Офлайн по умолчанию. В рантайме нет ни одного сетевого запроса, ни
  аккаунта, ни телеметрии, ни фоновых обновлений. Сеть нужна только при
  подготовке проекта, чтобы скачать зависимости и ffmpeg.
- Файлы остаются твоими. Библиотека это индекс, а не копия. Удалил
  приложение, файлы на месте. Перенес папку, пересканировал.
- SQLite, а не JSON. Библиотека на десятки тысяч записей с поиском и
  связями требует нормальной базы: транзакции, FTS5, бэкап перед
  миграцией.
- Сканер отдельно от плеера. Индексация идет с таймаутами (10 секунд на
  ffprobe и ffmpeg), ошибка по одному файлу не роняет весь скан, а
  попадает в список ошибок.
- `media://` вместо `file://`. Окно приложения не получает доступ к
  файловой системе напрямую, видео отдается через узкий протокол с
  белым списком расширений.
- Удаление через корзину. Ошибка в интерфейсе не должна стоить человеку
  архива.
- Русский и английский, светлая и темная темы. Интерфейс читают люди,
  а не только автор.

## Кому полезно

- Тем, у кого семейный архив: годы видео с телефонов и камер,
  разложенные по папкам и датам.
- Тем, кто снимает сам: скринкасты, поездки, события, и хочет находить
  запись по кадру, а не по имени файла.
- Тем, у кого локальная коллекция фильмов и сериалов, и нужен каталог без
  сервера и аккаунтов.
- Тем, кто работает без стабильного интернета или принципиально не
  грузит личное в облако.
- Тем, кто на Windows и не хочет ставить Linux или докер ради просмотра
  собственных видео.
- Тем, кто ценит предсказуемость: приложение не меняет интерфейс по
  расписанию и не просит логин.

## Кому не нужно

- Если у тебя десять видео в год, хватит проводника.
- Если нужно смотреть с телевизора, телефона или другого компьютера по
  сети, это не DLNA и не стриминговый сервер. Такого здесь нет.
- Если нужны автоматические постеры, описания и рейтинги из интернета,
  не подойдет: приложение принципиально не ходит в сеть, метаданные
  берутся только из самих файлов.
- Если прямо сейчас нужна мобильная версия или macOS/Linux, тоже нет:
  проверено на Windows, остальное не тестировалось.
- Если нужен готовый продукт с плеером и полным интерфейсом сегодня,
  подожди. Сейчас готово ядро, а не готовое приложение.
- Если нужен облачный каталог с доступом для друзей, это другая задача.

## Чем отличается

| Инструмент | Сильная сторона | Чего не хватает для этой задачи |
|---|---|---|
| Проводник Windows | всегда под рукой, ничего не ставит | нет библиотеки, тегов, поиска по кадрам, истории |
| VLC, mpv | проигрывают почти все, бесплатно | это плееры, а не каталог: нет организации и поиска |
| Plex | постеры, стриминг, клиенты на все устройства | сервер, аккаунт, сеть, транскодирование; чуждая модель хранения |
| Jellyfin | open source, self-hosted | нужен сервер и сеть, настройка тяжелее простой локальной библиотеки |
| Kodi | медиацентр с аддонами | рассчитан на TV-сценарий, тяжеловесен для просмотра за столом |
| Облачные галереи | доступ отовсюду | загрузка, подписка, приватность, зависимость от сети |
| VibeGallery | локальный каталог и плеер, ноль сети | ранняя стадия, только Windows, без стриминга |

- наблюдение за папками (chokidar);
- IPC библиотеки: корневые папки, запуск скана, удаление в корзину;
- 21 unit-тест, 2 e2e-теста, сборка NSIS и portable проверена.

В работе:

- сетка библиотеки, карточка видео, пустые состояния, прогресс скана;
- теги, коллекции, плейлисты, умные фильтры, поиск;

## Чего нет в репозитории

Тяжелое и локальное сознательно не хранится в git:

| Что | Почему | Как получить |
|---|---|---|
| `node_modules/` | зависимости ставятся на машине разработчика | `npm ci` |
| `resources/bin/` (~200 МБ) | ffmpeg и ffprobe, готовые бинарники | `npm run fetch:ffmpeg` |
| `tests/fixtures/videos/` | тестовые видео генерируются локально | `npm run fixtures:gen` |
| `release/`, `dist/`, `dist-electron/` | сборочные артефакты | `npm run build`, `npm run dist` |
| `docs/` | локальные отчеты и заметки | не нужны для работы |
| `*.db`, `*.log`, бэкапы | личные данные приложения | появляются при запуске |

Защита от случайного добавления тяжелого: `npm run repo:check`. Скрипт
падает, если в индексе или в истории git есть файлы больше 2 МБ или
запрещенные пути.

## Требования

- Windows 10 или 11 (основная платформа; код кроссплатформенный, но
  сборки проверены только на Windows);
- Node.js 24+ и npm 11;
- Git (для `repo:check` и работы с репозиторием).

## Первый запуск

```powershell
git clone https://github.com/DarkDaro/VibeGallery.git
cd VibeGallery

npm ci                     # зависимости, postinstall проверит ABI better-sqlite3
npm run fetch:ffmpeg       # скачает ffmpeg и ffprobe в resources/bin (вне гита)
npm run fixtures:gen       # создаст тестовые видео для разработки и тестов

npm run dev                # запуск приложения
```

Если `npm ci` недоступен (нет `package-lock.json`), используйте
`npm install`.

## Команды

| Команда | Назначение |
|---|---|
| `npm run dev` | режим разработки с HMR |
| `npm run build` | typecheck и production-сборка |
| `npm run dist` | NSIS-инсталлятор и portable (нужен `fetch:ffmpeg`) |
| `npm test` | unit-тесты (Vitest в Electron-рантайме) |
| `npm run e2e` | Playwright-тесты; перед первым прогоном нужен `npm run build` |
| `npm run lint` | ESLint, типы проверяет `npm run typecheck` |
| `npm run repo:check` | предохранитель от тяжелых файлов в git |
| `npm run fixtures:gen` | пересоздать тестовые видео |
| `npm run fetch:ffmpeg` | скачать ffmpeg и ffprobe |

Особенности тестов: нативные модули собраны под ABI Electron, поэтому
Vitest запускается через `ELECTRON_RUN_AS_NODE=1 electron`, а не через
чистый Node. E2E поднимают production-сборку, поэтому сначала
`npm run build`, затем `npm run e2e`.
